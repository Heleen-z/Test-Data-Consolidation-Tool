# 用户操作说明

## 1. 准备目录

- 输入目录：允许包含多层子目录和不同测试类型的文件。
- 输出目录：程序会创建合并工作簿、验证报告和处理日志。已有同名合并文件不会覆盖，新文件名会自动增加时间戳。
- 模板目录：使用项目随附的 `Raw data standard Title`。模板文件名用于确认测试类型，黄色 `FFFFFF00` 和绿色 `00B050` 单元格表示需要合并的字段。

程序会排除模板目录、输出目录以及文件名中包含“表头”“template”“header”的模板副本。原始文件始终只读。

## 2. 理解 Pre-check 状态

- 有效：类型、模板、横轴和全部高亮字段均可用。
- 有警告但可合并：横轴有效且至少命中一个高亮字段；缺失高亮字段会在结果中补空。
- 无效：无法识别类型、文件损坏、没有数据、缺少横轴、未命中任何高亮字段或字段匹配有歧义。
- 重复并跳过：文件 SHA256 与已扫描文件完全相同。

Pre-check 结果表会将长文件名、缺失字段和检查信息自动换行显示；检查摘要会压缩常见的冗长错误，以便在不横向滚动的情况下浏览一整行。进入“合并”步骤后，所有“有效”和“有警告但可合并”的文件默认勾选。取消勾选某个文件可将其排除在本次合并之外；选择状态会写入验证报告。

字段匹配忽略大小写、全角/半角空格、首尾空格和连续空格，但不会模糊猜测单位。不同名称需要在 `config/app_settings.yaml` 的 `matching.aliases` 中配置明确别名。

## 3. 理解下载结果

- 每种测试类型形成独立工作表，同一类型的文件纵向合并。
- 必要的日期、时间、循环或频率列显示在左侧，即使该列没有在模板中高亮。
- 其余可见业务列仅来自模板黄色或绿色字段。
- `Source_Index` 记录来源文件、哈希、行数、解析器、状态和轴范围。
- 类型表内隐藏的 `__source_id` 可关联 `Source_Index`，用于追溯每一行。
- 超过 Excel 单表上限时使用 `T09_1`、`T09_2` 等工作表，不丢弃数据。

绝对时间类型按时间整体排序；相对时间和循环类型保持来源文件分组，并在每个来源文件内部排序，因此两个都从 0 开始的文件不会被交叉混排。

## 4. 图表

选择测试类型后，可以多选来源文件和数值通道。页面横轴范围控件从完整数据重新筛选；图表不会降采样、聚合或删除任何符合筛选条件的数据点，显示的每个点都来自真实原始记录。数据量很大时，浏览器绘制可能需要更长时间。

已选通道会自动分成“温度通道”和“其他通道”两张图。温度识别包括 TCK、Temperature、Temp、Ts、T1 等常见字段和温度单位；SPEED、TORQUE、POWER、ACCELERATION 等会显示在另一张图，避免温度量程压缩其他信号。仅选择其中一类时只显示对应图。

每张图底部的加高范围条显示微缩全局趋势，用于缩放或拖动横轴；两张图同时存在时，任一图的横轴操作都会同步到另一张图。右侧纵向范围条只控制当前图：拖动上下手柄缩放纵轴，拖动中间选中区纵向平移。双击图表可恢复横轴全范围及当前图的纵轴范围。

图表下方的“导出当前 10 个轮次高清截图”按钮仅在循环（cycles）测试中显示：它以当前图的横轴起点为起点，截取连续 10 个 cycle 范围内的所有真实点。其他测试类型的按钮会导出当前横轴范围。导出的 PNG 为 900 × 3600 像素（宽高约 1:4）；温度和其他通道同时存在时会按上下布局保留为同一张图，两个纵轴保持独立。导出全程在本机浏览器组件内完成，不上传数据，也不降采样。

## 5. 使用记录

点击“开始合并”并成功生成结果后，工具保存一次成功使用记录。一个批次包含多个文件仍只记一次；部分文件失败但生成结果也记一次，并附带失败数量。项目名称自动取输入目录名称。启动、Pre-check、查看及下载不会新增记录。

默认“仅本地记录”，网站列表建立后可通过 EXE 旁的 `local-config.yaml` 切换为 `online`，后台上传到 AI Portal。页面下方显示同步状态；网络不通时记录留在本地，后续会话或转换时补传。建表字段和接入步骤见 [AI Portal 使用记录说明](AI_PORTAL_USAGE_LOGGING.md)。

## 6. 故障处理

查看输出目录的 `Processing Log.txt` 和 `Validation Report.xlsx`。联系支持人员时请附上这两个文件和错误截图，不要发送未经脱敏的测试数据。
